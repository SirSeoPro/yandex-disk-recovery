# Скрипт пакетной выгрузки данных с яндекс диска

Скрипт на Windows PowerShell для скачивания всего содержимого Яндекс.Диска (или отдельной папки) на локальный диск с сохранением структуры папок — через официальный REST API, без сторонних клиентов и без ввода пароля в скрипт.

## Быстрый старт
1) Выпустите токен в своём личном кабинете https://yandex.ru/dev/disk/poligon/
2) Сохраните скрипт локально в папку (в моем примере F:\Ya.Disk)
3) ВЫполните команды, в PowerShell:

```
cd F:\Ya.Disk 
powershell -ExecutionPolicy Bypass -File ".\yandex_disk_sync_portable.ps1" -Token "ВАШ_ТОКЕН" -Threads 10
```
4) Если файлов много - оставляйте на ночь

## Принципы работы

### 1. Авторизация через OAuth-токен, а не логин/пароль

Скрипт не знает пароль от аккаунта и никогда его не запрашивает. Используется персональный OAuth-токен Яндекс.Диска (получается один раз вручную на https://yandex.ru/dev/disk/poligon/ после входа в аккаунт) с правами на чтение/запись Диска. Токен передаётся в заголовке `Authorization: OAuth <token>` при каждом запросе к `https://cloud-api.yandex.net/v1/disk/resources`.

### 2. Два независимых этапа: листинг и скачивание

- **Фаза 1 — инвентаризация.** Скрипт рекурсивно обходит дерево папок через `GET /v1/disk/resources` (с пагинацией по `offset`/`limit`) и строит плоский список файлов `{RemotePath, LocalPath, Size}`. Сетевых запросов на передачу данных на этом этапе нет — только метаданные.
- **Фаза 2 — скачивание.** Для каждого файла сначала запрашивается временная прямая ссылка (`GET /v1/disk/resources/download`), затем по ней выполняется сам `Invoke-WebRequest`.

Разделение важно само по себе: листинг — дешёвая операция, которую не хочется повторять, а скачивание — дорогая и склонная к сбоям, которую нужно уметь безопасно повторять частично.

### 3. Кеш листинга — не пересканировать дерево без необходимости

Результат фазы 1 сохраняется в JSON-файл рядом со скриптом (`_listing_cache.json`). Если файл существует, следующий запуск сразу загружает список оттуда и не делает ни одного `LIST`-запроса к API. Это осмысленно, когда состав файлов на Диске не меняется между запусками — скрипт не платит временем за повторное сканирование того, что уже известно. Если файлы всё-таки добавлялись/удалялись — явный флаг `-RefreshCache` пересканирует всё заново.

### 4. Докачивание, а не перекачивание (идемпотентность)

Перед каждым файлом скрипт проверяет: существует ли локальный файл и совпадает ли его размер с размером на Диске. Если да — файл пропускается. Это значит, что скрипт можно останавливать (`Ctrl+C`, закрытие окна, сбой питания) и запускать заново сколько угодно раз — он продолжит с того места, где остановился, не тратя трафик на уже скачанное.

### 5. Параллельность через пул runspace, а не процессов

Для скачивания нескольких файлов одновременно используется `RunspacePool` (`[runspacefactory]::CreateRunspacePool`) — несколько лёгких потоков выполнения внутри одного процесса PowerShell, без накладных расходов на запуск отдельных `powershell.exe` для каждого файла. Параллелизм настраивается (`-Threads`, по умолчанию 4); сама раздача работы реализована как очередь задач с ограничением на число одновременно активных (а не "запустить всё и ждать") — это даёт возможность вовремя остановить набор новых закачек (например, при нехватке места) и живьём отслеживать зависшие потоки.

### 6. Устойчивость к сбоям — ошибка одного файла не останавливает скрипт

Каждая закачка оборачивается в `try/catch` с ограниченным числом повторов (`-RetryCount`, по умолчанию 3, с паузой `-RetryDelaySec` между попытками). Логика разделяет два типа ошибок:

- **Таймаут** (сервер не отвечает) — повторять бессмысленно, скрипт сразу помечает файл как неудачный и переходит к следующему.
- **Прочие ошибки** (например, `500 Internal Server Error`) — вероятно, временный сбой на стороне сервера, имеет смысл повторить попытку.

Листинг папок защищён той же логикой: если конкретная папка не отвечает после всех попыток, пропускается только она, а не всё дерево.

### 7. Внешний "сторож" зависших потоков

На практике `-TimeoutSec` у `Invoke-WebRequest` не всегда срабатывает, если передача данных зависла уже после установления соединения (подтверждено эмпирически: поток мог висеть часами, не выбрасывая исключение). Поэтому таймаут продублирован снаружи: главный поток отслеживает время жизни каждой параллельной задачи и, если оно превышает `-JobTimeoutSec`, принудительно останавливает её (`PowerShell.Stop()`), независимо от того, что происходит внутри. Это настоящая защита от зависания, а не только надежда на корректность HTTP-клиента.

### 8. Безопасное атомарное сохранение файла

На Диске встречаются файлы и папки с "ломаными" именами (например, незакрытая квадратная скобка `[` — судя по всему, результат обрезанного когда-то имени). `Invoke-WebRequest -OutFile` пытается резолвить путь как wildcard-шаблон и падает на таких именах, хотя `New-Item`/`Move-Item` — нет. Поэтому файл сначала скачивается во временную папку с безопасным именем на том же диске (`_yadisk_staging_tmp`), а затем переносится в целевое место через `Move-Item -LiteralPath` (перенос в пределах одного диска — это переименование, не копирование, так что быстро и не требует двойного места). Везде, где это в принципе возможно, используется `-LiteralPath` вместо `-Path`, чтобы PowerShell не пытался интерпретировать служебные символы в реальных именах файлов как wildcard-паттерны.

### 9. Контроль свободного места

Перед стартом каждой закачки поток проверяет, сколько места останется на диске после неё. Если прогнозируемый остаток опускается ниже `-MinFreeGB` (по умолчанию 2 ГБ) — выставляется общий флаг остановки: все потоки доканчивают то, что уже начали, но новые не запускаются. При параллельной загрузке проверка идёт по каждому потоку независимо, поэтому фактический остаток места может на короткое время просесть чуть ниже порога — на размер (Threads − 1) ещё летящих файлов.

### 10. Логирование и диагностика

Все события (листинг, скачивание, повторы, ошибки, остановка по месту) пишутся с таймстампом в `_sync_log.txt` в целевой папке — через именованный `Mutex`, чтобы параллельные потоки не портили друг другу строки при одновременной записи. Отдельно, в `_failed_downloads.txt`, копится построчный список: что не скачалось и почему — чтобы было видно, что нужно перекачать вручную или разобрать отдельно.

## Требования

- Windows PowerShell 5.1 (встроен в Windows, отдельно ставить ничего не нужно).
- OAuth-токен Яндекс.Диска с доступом к Disk REST API.


## Параметры

| Параметр | По умолчанию | Назначение |
|---|---|---|
| `-Token` | — | OAuth-токен строкой |
| `-TokenFile` | — | путь к файлу с токеном (альтернатива `-Token`) |
| `-RemotePath` | `/` | какую папку на Диске качать |
| `-LocalRoot` | `F:\Ya.Disk` | куда сохранять локально |
| `-Threads` | `4` | число параллельных закачек |
| `-MinFreeGB` | `2.0` | порог остановки по свободному месту |
| `-RetryCount` | `3` | число попыток на не-таймаут ошибки |
| `-RetryDelaySec` | `5` | пауза между попытками |
| `-TimeoutSec` | `20` | таймаут одного сетевого запроса |
| `-JobTimeoutSec` | `90` | жёсткий потолок на весь файл (внешний сторож) |
| `-MaxDownloads` | `0` (без ограничения) | ограничить число файлов за запуск (для тестов) |
| `-CacheFile` | `_listing_cache.json` рядом со скриптом | где хранится кеш листинга |
| `-RefreshCache` | выкл. | игнорировать кеш и пересканировать дерево |

## Известные ограничения

- Кеш листинга не отслеживает удаления/добавления файлов на Диске автоматически — при изменениях нужен `-RefreshCache`.
- Проверка свободного места при параллельной загрузке приблизительная (см. п. 9).
- Сканирование дерева (фаза 1) однопоточное — это осознанный выбор: листинг дешёвый, а при наличии кеша не выполняется вообще.
